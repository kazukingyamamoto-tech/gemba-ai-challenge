# 現状のLPと検討内容の齟齬

作成：bridge AI　2026-09-27
対象：公開中の [https://bri-dge-ai.github.io/ai-business-contest-lp/](https://bri-dge-ai.github.io/ai-business-contest-lp/)（`index.html`）と、`cases/` および `design/` の検討内容

LPは2026年8月時点で作られており、その後のケース設計・データ設計の決定が反映されていない。反映が必要な箇所と、そもそも運営として決まっていない箇所を分けて整理する。

---

## 1. 齟齬（直す必要がある）

### 1-1　ケース文が抽象的で、決めた2ケースと接続していない　【重要】

**LPの現状**（`暫定` バッジ付き）

> クライアント企業の現場課題を特定し、データ分析やAI実装を通じて、営業利益率の改善を促すビジネスアイデアを創出せよ。

**検討内容**：惣菜工場（HACCP）と農業法人（JGAP）の2ケース。舞台・登場人物・手元のデータ・成功の形まで確定済み。

**何が食い違うか**

| 点 | LP | 検討内容 |
| --- | --- | --- |
| 粒度 | 1文の抽象的な指示 | 舞台と当事者が具体的に決まっている |
| 語り口 | 三人称の指示文 | 「あなたは代表です」という二人称 |
| 成果指標 | 営業利益率 | クレーム年40件／記録と提出の月25時間。**営業利益率はどちらのケースにも出てこない** |
| ケース数 | 1つ | 2つ |

営業利益率は、中小企業の現場課題としては迂遠な指標になっている。決めた2ケースの成功の形はいずれも**現場で数えられる数字**であり、ここは置き換えが必要。

### 1-2　「クライアント企業」という表現

**LPの現状**：「クライアント企業の現場課題を特定し」

**検討内容**：舞台は架空企業。データは全件合成で、実企業のデータは使わない。

実在企業が課題とデータを提供すると読める書き方になっている。協賛企業が実データを出す形に変えるのか、架空企業＋合成データで通すのかを決め、表現を合わせる必要がある。**現在の設計は後者**。

### 1-3　従来ビジコンとの違いに、今回の軸が入っていない

**LPの現状**

- データサイエンスやAIを学んでいる学生を対象としていること
- データ分析やアプリのプロトタイプ開発を組み込んだビジコンであること

**検討内容**：GEMBAの軸は「**記録はあるのに活かせていない現場**を扱う」こと、そして「**精度ではなく方向性で競う**」こと。

現在の2点は「AIを扱うビジコン」の説明にとどまっており、他のAIハッカソンと区別できていない。上記2点を足すと、参加者の期待値も揃う。

## 2. LPに記載がなく、追加が必要なもの

### 2-1　審査の観点

**検討内容**：①アプローチの筋 → ②効き方の理屈 → ③実装の完成度。**性能を3番目に置くことを、募集要項と当日の説明で明示する**と決めている。

明示しなければ参加者は精度を上げに行く。LPに書くべき項目。

### 2-2　データの配布方法とタイミング

**検討内容**：段階公開。

| 段階 | 時期 |
| --- | --- |
| サンプル（全体の約1割） | 募集開始時ないし事前プログラム |
| 全量（2年分） | 開催当日 |
| 別期間データ | 審査時のみ（運営保持） |

参加者にとって事前に準備できるかどうかは参加判断に関わる。現在のLPはデータに一言も触れていない。

### 2-3　必要な環境・スキルの具体

**LPの現状**：参加条件に「使用可能なパソコンを持っていること」。

**検討内容**：配布データは1ケースで20ファイル前後、最大31万行のログを含む。一方で「1・2段目のデータだけで成功の形に届く」設計なので、**表計算ソフトだけでも取り組める**。

この2つを書き分けないと、「重い環境が必要そうだ」と誤解されて応募が減るか、逆に準備不足で当日詰まる。

### 2-4　チーム編成の方法

事前プログラムでチームを発表する流れで組んでいるが、LPに記載がない。個人応募か、チーム応募可か、運営が編成するのか。

### 2-5　賞・表彰

LPに記載なし。参考にしたBusiness Contest KINGは賞金100万円を掲げている。GEMBAの規模でどうするか。

### 2-6　事前プログラムの日程

LPの参加条件に「事前イベントおよび2日間の予定に参加できること」とあるが、日程が書かれていない。参加可否の判断ができない。

## 3. 運営として未決で、決めないと書けないもの

| # | 論点 | 選択肢・補足 |
| --- | --- | --- |
| 1 | **2ケースをどう割り当てるか** | チームが選ぶ／運営が割り当てる／全チーム同一ケース。2ケース用意すると審査の比較が難しくなる一方、成果物は分散する |
| 2 | **協賛企業が実データを出すか** | 出すなら 1-2 の表現は現状のままでよいが、データ設計をやり直すことになる。出さないなら架空企業として明記する |
| 3 | 生成AIサービスの利用と費用負担 | 参加費2,000円に含めるのか、各自負担か、運営がAPIキーを配るか |
| 4 | 発表形式 | 全チーム発表か、予選→決勝の段階審査か。チーム数次第 |
| 5 | 会場・参加費の確定 | LPでは `予定` バッジ付き |
| 6 | 参加登録の受付開始時期 | LPは「近日開始予定」 |
| 7 | メンター・審査員の構成 | 協賛企業の社会人が入る前提で流れを組んでいる |

## 4. LPの記述で、そのまま活かせるもの

齟齬がなく、検討内容と整合している部分。

| セクション | 状態 |
| --- | --- |
| Background（開催背景） | 「AIの知識そのものではなく、それを課題を解決する手段として使いこなす力」という主張は、今回の設計と完全に一致している |
| Concept（AIを、現場の価値へ。） | 整合。ただし「現場」が作業現場と読まれる余地があるため、ビジネスの意思決定を扱うことを本文で補うとよい |
| Overview の参加条件 | 「AIやデータサイエンスのビジネス現場への利活用に興味があること」は整合 |
| Community（Slack・LINE） | 検討内容と無関係。そのまま |
