## 1. 背景

**GAP**（農業生産工程管理）は、食品安全・環境保全・労働安全の観点から農作業の手順を定めて記録する取り組みで、第三者機関の審査を経て認証されます。日本発の認証が**JGAP**です。大手小売の取引条件として求められることが増えています。

農業の記録で特に重いのが農薬です。農薬には**PHI（収穫前日数：散布から収穫まで空ける日数）**と**使用回数の上限**がラベルで定められ、違反すると残留農薬基準を超えるおそれがあり、出荷停止や認証取消につながります。さらに農薬は、同じ有効成分でもメーカーによって**商品名**が異なるため、記録を「商品名で書くか、有効成分名で書くか」が提出先ごとに分かれます。

栽培履歴（生産履歴）の提出は出荷先ごとに様式が異なり、項目名・単位・集計期間もばらばらです。加えて補助金を受けていれば、行政様式での実績報告も必要になります。

## 4. 記録が4回書き直される経路

```
畑（作業者6名）
  │ LINEグループに報告（テキスト＋写真、1日5〜15件）
  ▼
代表の妻（夜、台所）
  │ 目で読んで転記
  ▼
営農管理アプリ（JGAP対応・作業/農薬/肥料/収穫/出荷）
  │
  ├─→ ① JGAP審査用の記録（アプリから出力できる：唯一楽な経路）
  ├─→ ② スーパーA社「栽培履歴書」Excel：品目ごとに別シート、農薬は商品名、月単位
  ├─→ ③ スーパーB社「生産履歴」Excel：農薬は有効成分名で記載、収穫ロット単位
  ├─→ ④ スーパーC社：Web入力用CSV、農薬コード必須（同社のコード表に従う）
  └─→ ⑤ 補助金実績報告（行政様式）：作付面積・労働時間・販売金額、四半期単位
```

②〜⑤は、元が同じ作業記録なのに、**項目名・単位・集計期間・農薬の呼び方がすべて違う**ため、アプリの出力を見ながら手で作り直しています。

---

## 5. すでに解決を試みたこと

- **2年前に営農管理アプリを導入**。JGAPの記録はこれで出せるようになった
- **CSV出力からExcelマクロを作ろうとした**が、出荷先の様式が毎年少し変わり、1年で使えなくなってやめた
- **作業者にアプリを直接入力させようとした**が、畑で手袋をしたまま項目を選ぶのが現実的でなく、LINE報告に戻った
- **農薬の商品名と有効成分名の対応表を自作した**が、新しい農薬を使うたびに更新が必要で、半年で放置された

→ 記録の入口（LINE）と出口（4つの様式）のあいだの変換が人力のまま残っている。

## 6. 配布用ケース文

> あなたは、野菜を作る従業員9名の農業法人の代表です。
>
> 記録と提出にかけている時間は、月に25時間を超えます。作業者は畑からLINEグループに「A圃場 トマト 摘芯 3名 9:00-11:30」と写真付きで報告し、事務を担う妻が夜にそれを読んで営農管理アプリへ入力します。JGAPの記録はアプリから出せるようになりました。
>
> ところが出荷先のスーパー3社は、それぞれ別のExcel様式で栽培履歴の提出を求めます。A社は農薬を商品名で、B社は有効成分名で、C社は自社の農薬コードで書くよう指定してきます。集計単位も月・収穫ロット・作付とばらばらです。補助金の実績報告は行政の様式で、労働時間の集計を求められます。どれも元は同じ作業記録なのに、様式ごとに手で書き直しています。去年は誤記で1件差し戻され、出荷先から改善を求められました。来月末には、A社への提出と四半期の補助金報告が重なります。
>
> 同じことを4回書いている、とあなたは思っています。記録のせいで、畑に出る時間が減っています。
>
> 手元には2年分のLINEログが約7,000件（写真とボイスメッセージ付き）、営農管理アプリのデータと操作ログ、出荷先3社の様式と過去の提出物、差し戻しの履歴、補助金の実績報告、アプリ導入前の手書き日誌があります。
>
> **さて、AIを使って何をしますか？**
>
> **成功の形：記録と提出にかかる時間（月約25時間）を半分にし、提出物の差し戻しをゼロにする。**
>
> *方向性：提出をなくすことはできません。提出前の最終確認は人が行います。*

これも2条件です。時間だけなら「雑に作る」で達成でき、差し戻しゼロだけなら「今より丁寧に時間をかける」で達成できてしまいます。両立させる必要があることが判断を生みます。

## 7. 運営メモ：想定される方向（参加者には示さない）

| 方向 | 中身 |
| --- | --- |
| 変換を機械に寄せる | 様式間のマッピングを作る（最も素直な方向） |
| 入力を変える | LINEの書き方に型を与える。写真の使い方を変える |
| 確認だけを機械に任せる | 作るのは人、提出前チェックを機械が行う |
| **様式の側に手を入れる** | 出荷先3社に共通フォーマットを提案する材料を作る。技術の精度ではなく交渉で勝負する筋 |
| 記録の意味を変える | 栽培改善や販売に使えるようにして、記録のコストを別で回収する |
| 二重入力をなくす | LINEとアプリの転記そのものを経路から外す |

## 9. 意図的に仕込む「使い方の難」

| 種類 | 具体 |
| --- | --- |
| 圃場名の別名 | 「A圃場／Aハウス／上の畑／ハウス1」が同一。マスタに一部だけ記載 |
| 農薬名の3系統 | 商品名・有効成分名・現場略称が混在。B社様式は成分名、C社はコード必須 |
| コード表の不備 | C社の農薬コード表に、実際に使った農薬のうち3件が載っていない |
| 日付のずれ | LINE報告は作業当日、アプリ入力は夜または翌朝 → 1日ずれた記録が 約15% |
| 単位混在 | 収穫・出荷が kg / ケース / コンテナ / 本 で混在。ケースの入り数は出荷先ごとに違う |
| 伝票との不一致 | 出荷記録と請求データで数量が合わない行が 約3%（積み増し・返品・規格外の振替） |
| 労働時間の不在 | LINEには人数と時間帯があるが、アプリの作業記録に労働時間欄がない → 補助金報告は推計 |
| 写真だけの報告 | 本文なしで写真のみの投稿が 約8%。画像から作業を推定する必要がある |
| 音声だけの報告 | ボイスメッセージのみの投稿が30本。文字起こしは付けない |
| 様式の年次変更 | A社様式が2年目に列構成を変更。過去提出物は旧様式のまま |
| 過去の誤記 | B社への提出物に有効成分名の誤記が1件（差し戻し履歴と対応） |

**「正解」とは呼ばない。** 役割は「このデータは解ける」ことを運営が保証するための自己検証のみ。採点表には載せない。

| # | 仕込む事実 | 発見の経路 | 段 |
| --- | --- | --- | --- |
| A | 収穫前日数（PHI）のニアミスが2件ある（違反ではないが余裕1日） | 農薬使用記録 × 収穫記録 × 農薬マスタ | 1 |

## 11. 弱点と、対処の見込み

| 弱点 | 対処 |
| --- | --- |
| **構造化データが約4万行で3案中最少**。分析し甲斐に欠ける | 操作ログ1.6万行を足して「現状の作業時間を実測する」という筋を作った |
| **題材が一つの課題意識に収まる** | 「転記と提出の手間をどう減らすか」以外の課題が立ちにくい。成功の形を「時間半減＋差し戻しゼロ」の2条件にして経路は増やしたが、課題そのものの幅は広がらない。ただし「様式の側に手を入れる（出荷先への共通フォーマット提案）」という技術外の筋が出るのは強み |
| 業界が学生に遠い | 惣菜工場と同様。語り口では改善できるが、業界そのものは変えられない |
| 差し戻しが1件では傾向が読めない | 3年で5件に拡充した |
