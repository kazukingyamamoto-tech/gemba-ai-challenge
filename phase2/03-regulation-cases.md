近年の法改正で対応が義務づけられ、**記録は溜まるが活用は義務でない**制度を入口にしたケースの試作。HACCP（ケース3-1）と同じ構造を、別の業界に展開したもの。

## 1. 「成功の形」の書き方（このコンテストの核）

### 目指すのは、方向性で競えるケース

GEMBA AI Challenge で競ってほしいのは、**同じゴールに対して違う筋道を持ち寄ること**です。その次に性能が来ます。

この順序は「成功の形」の書き方だけで決まります。たとえば熱中症のケースで、成功の形を

> ❌ 「今日この現場のこの人が危ないと分かる」

と書けば、全チームが予測モデルを作り、**予測精度の競争**になります。データも配点もそこに寄り、アプローチの違いは評価されません。同じケースでも、

> ⭕️ 「夏場の搬送と早退を、工期を落とさずに減らす」

と書けば、予測で攻めるチーム、報告のしやすさで攻めるチーム、段取りの組み替えで攻めるチーム、現場環境の弱点を突くチームが並び、**なぜその方向を選んだのか**で競えます。

### 成功の形のチェックリスト

| # | 基準 | 悪い例 | 良い例 |
| --- | --- | --- | --- |
| 1 | **手段を表す語を含まない** | 予測する／要約する／検出する／分類する／検索できる／チャットで聞ける | 減る／増える／早くなる／止まらない |
| 2 | **現場の誰かの行動か、経営の数字が変わる形** | 「傾向が可視化される」 | 「職長が午後の段取りを変える」「クレームが減る」 |
| 3 | **異なる方向のアプローチが3つ以上思いつく** | 到達経路が1つしかない＝手段を書いてしまっている | — |
| 4 | **測り方が言える** | 「現場が助かる」 | 「月○時間」「年○件」 |

**3が最も重要な検査**です。ケース文を書いたら、運営側で「この成功の形に、方向の違う解き方を3つ挙げられるか」を必ず試します。挙げられなければ、成功の形が手段に寄っています。

### 審査への接続

| 順位 | 見るもの |
| --- | --- |
| 1 | **アプローチの筋**：なぜその方向を選んだか。現場の誰が、いつ、どう使うのか |
| 2 | **成功の形への効き方**：その方向で数字が動く理屈が立っているか |
| 3 | **性能・完成度**：実際に動くか、精度はどうか |

性能を3番目に置くことを、募集要項と当日の説明で明示します。そうしないと参加者は精度を上げに行きます。

## 2. 案A：職場の熱中症対策（2025年6月義務化）

**制度背景**：2025年6月から、職場の熱中症対策が罰則付きで義務化された（改正労働安全衛生規則）。WBGT28℃以上または気温31℃以上の環境で連続1時間・1日4時間を超える作業がある事業者は、**熱中症のおそれがある者を早期に見つけて報告する体制の整備**と、重症化を防ぐ手順の作成・周知が義務となっている。

### ケース文

首都圏で戸建ての外構・造園工事を請け負う従業員35名の会社。現場は毎日15〜20か所に分散し、職長が朝と午後にWBGT計で測った値を、現場写真とともに社内LINEへ報告する。義務化にあわせて体調申告の仕組みも作り、気分が悪くなった作業員は職長経由で報告する。報告があれば涼所へ移し、必要なら病院へ運ぶ手順も文書にして全員に配った。

それでも去年の夏、熱中症で1名が救急搬送され、軽い症状での早退は12件あった。搬送された作業員は、前日も別の現場で「少しふらついた」と職長に話していた。その話はLINEに流れていたが、その日の報告の一部として埋もれ、翌朝には誰も覚えていなかった。

社長は「体制は作った。記録も毎日ある。それでも去年と今年で、何も変わった気がしない」と言う。

- **すでに記録していること**：WBGT測定記録（朝・午後）、社内LINEの現場報告（写真付き）、体調申告、作業日報、KY活動記録、勤怠（出退勤・残業・連勤）
- **それでも残る問題**：記録は「その日その現場の状態」として残るが、人・現場・季節を横断して振り返る機会がない。毎日の報告は流れていくだけで、去年の夏に何が起きたかを誰も参照していない
- **あるデータ**：WBGT測定記録2シーズン分、社内LINEログ（約8,000件・写真付き）、作業日報、体調申告記録、勤怠データ、KY活動記録、気象データ、過去の熱中症発生・早退記録、現場ごとの休憩所・給水設備の有無

### 成功の形

> **この夏の熱中症による搬送と早退を、前年より減らす。ただし工期と作業量は落とさない。**

*方向性：体調管理を会社が支配する道具にはしないでください。判断するのは職長と本人です。ウェアラブル端末の新規導入を前提としない案を歓迎します。*

### 運営メモ：想定される方向（参加者には示さない）

| 方向 | 中身 |
| --- | --- |
| 予兆を捉える | 不調の訴えを人軸でつなぎ、連勤・前日の作業とあわせて見る |
| 報告の摩擦を下げる | LINEの雑談がそのまま記録になる。職長が聞き方を変えられる |
| 段取りを変える | 午後の高WBGT現場への人の配置、休憩の入れ方、作業順の入れ替え |
| 現場環境の弱点を突く | 休憩所・給水設備のない現場に事故が偏っていないかを示す |
| 情報の出し方を変える | 朝礼で職長が3秒で読める1枚にする |
| 事後を回す | 早退12件から翌週の作業計画に反映される流れを作る |

6方向あり、うち予測を使うのは1つだけ。チェックリストの3を満たしている。

## 3. 案B：カスタマーハラスメント対策（2026年10月義務化）

**制度背景**：2026年10月1日から、カスタマーハラスメント対策が全事業主の義務となる（改正労働施策総合推進法）。労働者を1人でも雇う事業主が対象で、経過措置はない。方針の明確化、**相談体制の整備**、事後対応、抑止措置が求められる。

### ケース文

県内10店舗を展開する食品スーパー。従業員600名のうち約500名がパート・アルバイト。義務化にあわせて本部に相談窓口を設け、店長経由でも直接でも相談できるフォームを用意し、全従業員に周知した。

半年経って、窓口に上がってきた相談は18件。一方で、各店舗が毎日提出する店舗日報の「お客様対応」欄には、「レジで20分間どなられた」「試食の量が少ないと言われ、追いかけられた」「返品を断ったら店長を出せと1時間」といった記述が、月に100件を超えて書かれている。

パート従業員からは「これくらいで相談していいのか分からない」という声がある。退職者アンケートの自由記述には「お客様が怖かった」「クレーム対応が嫌だった」が並ぶが、離職理由の選択肢では「家庭の事情」が最多になっている。

本部の人事担当は「窓口を作って、措置は満たした。でも働いている人が守られたかというと、答えられない」と言う。

- **すでに記録していること**：相談窓口フォーム（18件）、店舗日報の「お客様対応」欄（全店・毎日）、サービスカウンターの電話録音、防犯カメラ映像（1か月保存）、退職者アンケート、勤怠データ
- **それでも残る問題**：実態は日報に書かれているが、日報は店長が読んで終わりで、本部は集計しない。何が「社会通念上許容される範囲を超えた」かの線引きが現場で共有されておらず、深刻なものだけが窓口に届く
- **あるデータ**：店舗日報2年分（自由記述・全10店舗）、相談窓口の記録、サービスカウンターの電話録音（約400時間・同意済み）、退職者アンケート3年分、勤怠・離職データ、レジの取消・返品ログ、店舗の立地・客層データ

### 成功の形

> **カスハラが理由で辞める人を減らす。そして、何かあったときに従業員が「言ってよかった」と思える状態にする。**

*方向性：従業員を監視したり、店長の評価に使う道具にはしないでください。また、顧客を一方的に問題客として分類する仕組みは求めていません。守るのは働く人です。*

### 運営メモ：想定される方向

| 方向 | 中身 |
| --- | --- |
| 実態を本部に届ける | 日報の記述を集約し、月次で人事が見る形にする |
| 線引きを現場に返す | 過去事例から「これは相談していい」の基準を現場の言葉で作る |
| 報告の摩擦を下げる | 日報を書くことが相談になる。二重に書かせない |
| 環境要因を突く | レイアウト・人員配置・告知物・レジ台数と発生の関係を見る |
| 対応の型を配る | うまく収めた対応を他店の初期対応として共有する |
| その場を支える | 発生中の店長に、次に何をするかを示す |
| 離職と結びつける | どの店舗・どの職場条件で人が辞めているかを示す |

## 4. 案C：介護のBCP策定（2024年4月義務化）

**制度背景**：2024年4月から、すべての介護事業所に業務継続計画（BCP）の策定が義務化された（未策定は介護報酬の減算対象）。自然災害編と感染症編を作り、研修と訓練を定期的に行うことが求められる。

### ケース文

特別養護老人ホーム1施設（入居80名）、デイサービス2か所、訪問介護1事業所を運営する社会福祉法人。職員120名。2024年の義務化に向けて自然災害編と感染症編のBCPをひな形に沿って作成し、以後は年2回の訓練と年1回の研修を実施して、記録も残している。

しかし去年9月の台風で実際に起きたのは、BCPに書かれていないことばかりだった。職員の子どもの預け先がなく出勤できない、非常用発電機の燃料が予定の業者から届かない、利用者家族からの安否確認の電話が鳴り止まず記録も取れない、近隣の被災した施設から受け入れを打診される。現場は職員のLINEグループで朝まで連絡を取り合い、なんとか回した。

そのLINEには、その夜に起きたことと判断の経緯がすべて残っている。しかし訓練記録には「実施した」「参加者32名」とだけ書かれ、BCP本体は策定から2年半、ほぼ更新されていない。施設長は「次に同じことが起きても、また同じように朝まで電話することになる」と言う。

- **すでに記録していること**：BCP文書（自然災害編・感染症編）、訓練記録（年2回）、研修記録、ヒヤリハット報告、介護記録システム、勤務シフト、利用者ごとの個別避難計画
- **それでも残る問題**：実際に起きたことは職員のLINEとヒヤリハットに残り、BCPには反映されない。訓練は計画どおりに動く練習になっており、計画に書いていない事態を試していない
- **あるデータ**：BCP文書（現行版と初版）、訓練・研修記録3年分、台風・大雪・感染症発生時の職員LINEログ（約3,000件）、ヒヤリハット報告2年分、介護記録システム、勤務シフト2年分、職員の通勤手段・居住地（同意ベース・匿名化）、個別避難計画80名分、近隣施設との協定書

### 成功の形

> **次に同じことが起きたとき、現場が「どうするか」を探す時間を減らし、サービスを止めない。**

*方向性：BCPの文書を自動生成することが目的ではありません。人命に関わる判断は人が行います。*

### 運営メモ：想定される方向

| 方向 | 中身 |
| --- | --- |
| 経験を計画に還す | 災害時のLINEから起きたことを取り出し、BCPの抜けを示す |
| 訓練の設計を変える | 計画に書いていない事態のシナリオを作り、年2回の訓練で試す |
| その夜を支える | 夜間に判断すべきことの順序と連絡先を、状況に応じて出す |
| 人の制約を先に洗う | 通勤手段・家庭事情から、災害時に出勤できる人数を見積もる |
| 周辺の負荷を外す | 家族への安否連絡を集約し、現場から電話対応を外す |
| 依存関係を洗う | 燃料・食料・医薬品・人手の調達先と代替先を整理する |

## 5. 案D：医師の働き方改革（2024年4月）

**制度背景**：2024年4月から、医師の時間外労働に上限が設けられた（原則年960時間、特例水準で年1,860時間）。月100時間以上となる見込みの医師には**面接指導**が義務づけられ、勤務状況・睡眠・疲労の確認が求められる。勤務時間は客観的な記録による把握が必要。

### ケース文

200床の地域中核病院。医師45名。勤怠はICカード打刻で記録し、加えて医師本人が「労働」と「自己研鑽」の区分を自己申告する。事務職員2名が打刻と自己申告を突き合わせ、月末に上限管理の表を作る作業に毎月3日かかる。区分の判断は医師によって幅があり、事務から確認の依頼を出すが、返信が来ないまま締め切りが来ることもある。

上限超過は今のところ起きていない。しかし、月100時間に近づいた医師への面接指導の記録は、3年分を並べてもほぼ同じ文面で、「業務量の調整を検討する」「当直明けの負担軽減を図る」と書かれて終わっている。実際にタスクシフトが進んだ記録はない。

一方で、電子カルテには誰が何時にどの患者の記録を開き、何を入力したかのログが全部残っている。看護師への指示、検査のオーダー、退院サマリーの作成時刻も分かる。事務長は「上限は守れている。ただ、守るための作業が増えただけで、現場の負担は下がっていない」と言う。

- **すでに記録していること**：ICカード打刻、自己申告（労働／自己研鑽の区分＋コメント）、上限管理表、面接指導記録、宿日直許可の記録、電子カルテの操作ログ、当直日誌
- **それでも残る問題**：打刻は「いた時間」を示すが「何をしていたか」を示さない。それを埋めるための自己申告が、判断のばらつきと未提出を生んでいる。面接指導は義務を満たすために実施されるが、改善のための情報が集まっていない
- **あるデータ**：勤怠打刻3年分、自己申告データ（自由記述コメント込み）、上限管理表、面接指導記録（約200件・自由記述）、電子カルテ操作ログ（匿名化・3か月分）、当直・オンコール記録、タスクシフト会議の議事録、診療実績（患者数・手術件数）

### 成功の形

> **上限管理にかかる事務の月末作業を減らし、かつ医師の時間外労働そのものを下げる。**

*方向性：医師個人の評価や査定に使う仕組みは求めていません。診療の質を落とさずに負担を下げる道を探してください。カルテのログは個人が特定できない形で扱ってください。*

### 運営メモ：想定される方向

| 方向 | 中身 |
| --- | --- |
| 突き合わせを省く | 打刻・自己申告・カルテログの照合を機械側に寄せる |
| 自己申告をなくす | ログから労働／自己研鑽の区分候補を出し、確認だけにする |
| 面接の中身を変える | 「何に時間を使っているか」を面接の場に材料として出す |
| タスクシフト先を探す | 医師がやっている非医師業務を洗い出し、移せるものを示す |
| 当直の組み方を変える | オンコールと翌日勤務の組み合わせを見直す |
| 超過を月内に知る | 月末ではなく途中で分かる形にする |

## 6. 4本の比較

| | A 熱中症 | B カスハラ | C 介護BCP | D 医師の働き方 |
| --- | --- | --- | --- | --- |
| 成功の形 | 搬送・早退を減らす（工期は落とさない） | カスハラ理由の離職を減らす／言ってよかったと思える | 探す時間を減らし、サービスを止めない | 事務の月末作業を減らし、時間外も下げる |
| 想定される方向の数 | 6 | 7 | 6 | 6 |
| 扱うデータの種類 | 数値（WBGT・勤怠）＋LINE＋写真 | 自由記述＋音声＋アンケート | 文書＋LINE＋報告書 | ログ＋自由記述 |
| 現場感 | 高い（屋外・分散） | 高い（売場・パート） | 高い（夜間・災害時） | 中（院内・事務作業） |
| 倫理的な注意 | 体調監視になりうる | 従業員監視・顧客分類になりうる | 人命の判断を委ねない | 個人評価になりうる |
| データ準備の重さ | 中（LINE＋写真の合成） | 中（音声400時間の合成は重い） | 軽〜中 | 中（カルテログは3か月に限定） |

### 成功の形に「2つの条件」を置いている理由

A・B・Dは、成功の形を**2つの条件の組み合わせ**にしています。

- A：搬送・早退を減らす **＋ 工期を落とさない**
- B：離職を減らす **＋ 言ってよかったと思える**
- D：事務作業を減らす **＋ 時間外も下げる**

片方だけなら簡単に達成できてしまうためです。Aで「搬送を減らす」だけなら「暑い日は作業しない」で終わり、Dで「事務作業を減らす」だけなら集計の自動化で終わります。**2つ目の条件がトレードオフとして効くことで、どこで折り合いをつけるかという判断がアプローチの差になります。**

Cは、条件を1つにしていますが「サービスを止めない」自体に制約が含まれています（＝安全側に振り切って営業停止するのは不可）。

### 所感

- **Bが最も新しい**：2026年10月1日施行で、コンテスト時点では施行直後。「義務によってデータが溜まり始めたが、使い方が誰も分からない」をリアルタイムで扱える
- **Aが最も現場らしい**：屋外・分散・LINE・写真という組み合わせが、GEMBAという名前と最も合う。データも合成しやすい
- **Cは非構造データの比率が最も高い**：ほぼ全部が文書とチャット。数値分析に寄りたいチームには取りかかりにくい可能性がある
- **Dは成功の形が最も検証しやすい**：事務の作業時間と医師の時間外という2つの数字が明確。ただしカルテログは3か月分に絞る前提
